# Phase 10 — real analytics and reports

Implement only Module I / Phase 10 of the original roadmap. Current project membership and explicit workspace access authorize every report/export; guests and archives may read. No AI, billing, global administration, worker, deployment or paid provisioning. Publish the verified implementation and observe GitHub CI.

Add a lazy Analytics project section, pinned Recharts 3.10.1/react-is 19.3.0, semantic dark/light layouts, interactive series/unit controls, keyboard chart navigation and equivalent labeled data tables. Provide actual completion/status statistics, overdue task reports, existing planned workload/capacity, milestone progress, completed-sprint velocity, recorded activity trends and sprint burndown. Unknown estimates/capacity/history remain explicit. No invented productivity score or demo series.

Reports accept strict ordered UTC date ranges up to 90 days and an optional current same-project sprint. Defaults are the last 30 UTC days. Current completion/overdue/milestone snapshots describe current active tasks, including subtasks as distinct work items. Workload distributes entered estimates across explicit assignees and prorates known schedules in the selected range, reusing existing planning formulas. Unassigned, unscheduled and unestimated work remain visible. Completed-sprint selection uses actual completedAt dates and immutable commitment/delivery snapshots; velocity distinguishes completed task counts from entered estimate hours (not story points). Date ranges affect activity, planned workload and completed-sprint selection, not an invented historical project snapshot.

Existing history lacks per-sprint burndown observations. Add one indexed append-only collection of actual committed sprint totals: task count, done, remaining, entered estimated hours and unknown estimates. Project mutations capture changed active-sprint totals inside their existing transactions; start captures the initial state, completion captures the final state before unfinished work moves. Unchanged totals do not create extra observations. New observation failures roll back the related transaction. Legacy sprints start tracking at their next committed project change; reads never backfill or fabricate the past. Daily charts carry forward only previously observed values, leave unknown earlier dates blank, and stop at actual completion/current time. Scope changes and reopened work may increase the curve; label this honestly.

Separate contracts, repository, calculation/CSV service and controller/routes. Reports use bounded consistent transaction snapshots and current authority fences. Bounds: 5,000 active tasks, 50 milestones/sprints, 20,000 selected activity events and 10,000 selected burndown observations; exceedances return an explicit smaller-range error. CSV variants cover task, workload, milestone, sprint, activity and burndown data; quote fields, preserve Unicode/newlines and neutralize spreadsheet formulas. Actual authenticated downloads recheck current authority and use no-store/safe disposition. No public report URL or credentials.

Cover formulas, zero/unknown data, dates, safe CSV, actual transactions and observation rollback, same-day/latest values, scope changes/reopening/carryover, current grants/guests/archives/deletion, bounded rows beyond UI pages, real browser downloads, direct refresh/return paths, live updates, keyboard, both themes at 375/768/1440, axe, reduced motion and console errors. Run earlier regressions and full Compose CI; record any retried earlier scenario accurately. Add architecture/database/API/design/testing/README/progress/report/gallery evidence. Windows Docker/WSL/restart acceptance stays deferred and distinct from remote CI.
