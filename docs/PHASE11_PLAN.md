# Phase 11 — AI assistance and workflow automation

Implement only Phase 11 / Module J. Use the installed local Ollama `llama3.2:3b` model through a pinned server-side AI SDK provider; no paid provisioning, cloud transmission, model download or production seed. AI is disabled unless explicitly configured. Prompts receive bounded, freshly authorized project/task/planning context, never account/session data, file bytes or other projects. Treat project text as untrusted data. Validate structured output and every referenced task identifier. Render plain text; generation cannot execute tools or change product data.

Provide project assistant, natural-language task generation, subtask breakdown, summaries, risk/blocker suggestions, weekly status reports, priority suggestions and natural-language search assistance. Persist private, actor-owned generation records with snapshot fingerprints, provider/model, state and usage. Show errors, missing context, limits and unavailable models truthfully. Generation retries use stable identifiers; quota reservations are transactional and failed attempts count. Bound input/output, execution time, concurrency, daily actor/organization usage and history pages.

Task/subtask and priority proposals remain drafts. Let users edit/select them, preview exact changes and confirm application. Recheck current membership, archive status, snapshot and task versions inside one transaction. Apply through existing task persistence/validation and activity/observation paths; retries cannot duplicate tasks. Guests cannot apply changes. No deletion, assignment, arbitrary tools or externally transmitted messages are offered to the model.

Add explicitly enabled, manager-controlled daily risk and weekly status draft workflows. Configurable UTC schedules and a separate persistent BullMQ worker use durable MongoDB workflow/run records; Redis carries identifiers only. Fresh authorization and provider configuration are checked on every execution. Catch up once per missed period, retain bounded attempts, prevent duplicate outputs, expose status/errors and allow pause/delete/manual execution. Automation generates private reviewable drafts; it cannot apply AI changes or send email/messages. No enabled rules by default. Worker health and recovery commands remain separate from the API.

Verify schemas, context isolation/injection boundaries, real provider transport and local model generation, malformed output/references, quotas/concurrency/idempotency, unavailable/timeouts, authority revocation, atomic apply/rollback/stale snapshots, schedule boundaries, duplicate jobs, worker restart and revoked/paused workflows. Integration and browser fixtures use an explicitly labeled deterministic test provider; distinguish those from live-model evidence. Exercise all eight modes, task/priority review, workflows, errors, keyboard focus, reduced motion and dark/light at 375/768/1440 with axe. Run earlier regression and full Compose CI, inspect retries, retain screenshots and update architecture/database/API/design/testing/README/progress/report. Publish to the existing private repository. Stop before Phase 12.

Windows Docker/WSL and named-volume restart acceptance stay deferred. Local model verification uses existing Ollama; Redis-backed worker verification runs on real Compose Redis in CI if local Redis is unavailable. Never count unexecuted checks as passed.
