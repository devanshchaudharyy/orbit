# Phase 11 — AI assistance and workflow automation

Implemented 15 October; verification continued 16 October 2026. [Implementation plan](PHASE11_PLAN.md).

Phase 11 is complete and published. Full Compose CI passed, including real Redis worker verification. Local Windows Docker/WSL and named-volume restart acceptance remain deferred; those unexecuted checks are not counted as passed. Phase 12 has not started.

Implemented server-side local Ollama generation through AI SDK 7.0.140 / openai-compatible 3.0.68; the SDK, model adapter and BullMQ 6.3.15 stay outside the browser bundle. AI defaults to disabled. Endpoint validation requires locally addressed inference; no cloud fallback is configured. The installed `llama3.2:3b` model requires no new provisioning or model download. Optional MessagePack native acceleration is explicitly disabled; no build script approval is required for it.

Eight modes cover project assistance, task proposals, subtask breakdown, summaries, risk/blocker suggestions, weekly status reports, priority suggestions and natural-language matching of existing tasks. Context is current authorized project/task/planning data and up to 100 recent events in the last seven UTC calendar days. Task scope includes the selected task and its direct subtasks; project scope supports at most 100 active work items. Descriptions are explicitly shortened, recent history can be marked truncated, and context over 64 KiB is rejected. No other project, account credential, file bytes or network search is included. Untrusted project text stays data inside the prompt. Dynamic schemas restrict each mode and identifiers; separate server validation rejects malformed, foreign or unsupported output. Validation is not a factual-quality guarantee or an injection-proof claim. Plain-text results explicitly require review.

Private durable runs retain actor, request identity, snapshot hash, provider/model, result/error, timestamps, reported tokens and created task IDs. Daily UTC quotas are 20 attempts per actor per organization and 100 per organization. Failed attempts count; stable retries reuse their original result. Partial unique indexes enforce two concurrent running generations globally and one per actor. Generation has a 90-second transport deadline and a 120-second durable lease. Apply rechecks current authority, archive status and exact current context, then uses existing task validation, history and observations in one transaction. Edited/selected tasks and priorities require explicit confirmation; applying the same selection again cannot duplicate work. No destructive action, assignment or external publication tool is exposed.

Manager-controlled daily risk and weekly status workflows default to paused. Saving explicitly confirms delegation to the current owner. A separate persistent worker dispatches durable due records to BullMQ; Redis jobs contain only identifiers. Current account/project management rights and workflow version are checked again at execution and before output commit. Missed periods catch up once; successful/failed attempts advance to the next UTC schedule. Three exhausted worker retries record a visible failure and advance the schedule. Pausing/deleting a workflow prevents a stale in-flight result from becoming ready. Drafts remain private to the workflow owner; schedules never apply AI changes or send messages. A recent successful dispatch heartbeat is distinct from model configuration.

## Commands and recovery

Local model context capacity depends on Ollama configuration. Live smoke evidence covers small synthetic inputs; large-project model quality/context retention has not been benchmarked. For larger scopes, optionally create a local alias with `ollama create orbit-local -f infra/ollama/Modelfile.example`, set `AI_MODEL=orbit-local`, and restart the API. This reuses installed weights; the example is preparation only and was not executed. Choose a context size that fits available memory, or select a smaller task scope. The OpenAI-compatible endpoint requires model configuration to change context size, as described in the linked official compatibility documentation.

`pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`, `pnpm build`, `pnpm test:ai:integration`, `pnpm test:ai:e2e`, `pnpm test:ai:live`, `pnpm test:ai:worker`, and the complete earlier regression. The browser fixture is explicitly deterministic and isolated at API 4002 / web 5175, with real MongoDB and SDK HTTP transport; it is not live-model evidence and leaves the normal preview alone.

For local AI, set `AI_PROVIDER=ollama` in ignored `.env.local` and run the persistent API, with the chosen installed model available in Ollama. Or start the owned fixture using `pnpm auth:fixture:ai`; stop a previous owned fixture first. Default `pnpm auth:fixture` leaves AI disabled unless the calling environment enables it. No credentials belong in `VITE_*` variables. [Ollama compatibility](https://docs.ollama.com/api/openai-compatibility), [AI SDK structured output](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data).

After Docker/WSL prerequisites are installed, use `pnpm setup`, `pnpm infra:up`, `pnpm infra:check`, then `pnpm worker` and `pnpm worker:check` in separate terminals. For the isolated Compose suite, use `pnpm test:auth:compose`; it runs worker integration against the isolated test database. Preserve volumes and follow the separate restart sentinel in [TESTING.md](TESTING.md). [BullMQ guidance](https://docs.bullmq.io/guide/job-schedulers/); ORBIT's MongoDB due-record dispatcher owns its UTC schedules rather than using Redis scheduler records as the source of truth.
