# Phase 12 — test-mode SaaS billing

Implement Module K only. The user explicitly authorized building the integration while leaving live Stripe sandbox verification pending. This preserves local development and overrides Marketplace provisioning guidance: no Vercel resource, paid account, real charge, deployment, model call or system installation. Use Stripe 23.0.0 (Node >=20), server-only, test keys only; missing credentials produce unavailable feedback, never a simulated paid state. Stripe-hosted Checkout and Billing Portal handle payment details. The browser never receives keys or handles card data.

Organizations are billing boundaries. Owners manage checkout/portal; owners/admins read billing history. Other members may read a limited plan/entitlement summary, not invoices or provider identifiers. All cookie-session/profile/Origin/CSRF and current organization authorization checks remain. Provider sessions require an explicit action with confirmation; a success URL never grants access.

Free supports three workspaces and ten projects, including archives, per organization; Pro supports twenty/one hundred; Business supports one hundred/five hundred. Core tasks, collaboration, documents, dashboards and manual AI remain available. CSV analytics exports and enabled scheduled AI workflows require Pro/Business; scheduled workflow ceilings are ten/fifty per organization. Existing operational bounds still apply. Enforce quotas atomically in existing MongoDB transactions with a billing-account write fence. A downgrade retains data and permits reads/edits/removal while blocking additional over-limit resources and paid features. Worker execution and output commit recheck entitlements. No user-business data migration or paid seed.

Use configured monthly/yearly test Price IDs for Pro/Business. Read and validate actual recurring USD prices from Stripe; do not turn proposed marketing prices into authoritative charges. Flat organization subscriptions, quantity one. Fourteen-day trials are offered once per organization only, with explicit consent and payment-method collection. Trial, active, past_due, unpaid, incomplete, paused and canceled states remain distinct. Paid access requires active/trialing state and an unexpired provider period/trial. Price/quantity/customer/subscription mismatches fail closed. Portal performs plan changes, cancel-at-period-end and resumption; current provider state and signed webhooks update ORBIT.

Persist organization billing accounts, durable checkout operations, processed event identities and minimal invoice history. Customer/checkout creation uses durable stable idempotency keys, one pending checkout per organization, bounded API timeouts and safe retry identities. Recover returned sessions after network/commit failures; reject conflicting request reuse and expired operation reuse. Serialize synchronization with bounded durable leases; canonical current provider subscriptions prevent out-of-order webhook payloads from rolling state backward. Signature verification uses the raw body before JSON middleware. Reject live events/keys, malformed signatures, altered duplicate IDs and unsupported account scope. Duplicate processed events acknowledge without reapplying. Database/provider failures return retryable errors; never acknowledge uncommitted updates.

Build an original responsive organization Billing page with plan cards, monthly/yearly selection, actual-price or unconfigured states, current plan/trial/cancellation status, resource meters, entitlement explanations, recent invoice history/pagination, confirmation dialogs, checkout return reconciliation and truthful pending/error/retry feedback. Add scoped navigation and protected direct refresh. No unimplemented product links. Keep marketing copy consistent with test-only billing.

Verify contracts/configuration, permissions/privacy/CSRF, raw signed webhook transport and invalid/live/duplicate/reordered deliveries, safe retries/concurrent checkout, canonical state mapping, trial/cancel/downgrade, atomic resource limits, paid export/automation restrictions, durable reconnect and private history. Clearly label deterministic provider fixtures; test real Stripe SDK HTTP transport without claiming live sandbox results. Browser tests cover actual API/MongoDB, actions, permissions, errors, focus and both themes at 375/768/1440 with axe. Run regression, formatting/lint/types/tests/builds, production routes and Compose CI; retain screenshots and exact evidence. Publish to the existing private repository. Stop before Phase 13. Live sandbox checkout/webhook forwarding remains pending until the user configures credentials; Windows Docker/WSL/restart acceptance stays deferred. Llama remains unloaded.
