## Implemented

Explicit validated proxy IP/CIDR trust, uncached API errors/unknown routes, disabled API ETags, rejection of compressed JSON before inflation, safe encoding errors and explicit HTTP request/header/keepalive limits. Existing session/CSRF/Origin/tenant boundaries remain in force. The theme bootstrap is a small synchronous external script so the production CSP can prohibit inline scripts and JavaScript eval. PDF codecs receive the narrower WebAssembly permission. Accessible render-failure recovery focuses safe feedback and requires deliberate reload instead of replaying writes.

Non-root multi-stage production API/web images, production-only offline packaging, separate optional worker with a compiled heartbeat probe, private network/proxy trust, HTTPS, security headers/CSP, gzip, immutable hashed assets, uncached HTML/API, SPA refresh, WebSocket upgrades and bounded runtime resources. Build context excludes secrets/local configuration/test artifacts; production packages include compiled files only. No public binding, registry push or provisioning is performed.

New production smoke orchestration exercises actual HTTPS browser/API/database/STARTTLS email state, secure cookies, Origin/CSRF, persisted organization/workspace/project/task writes, rich-text documents, private Garage PDF upload/worker preview/exact download, lazy charts, private access, refresh, escaped text, themes, keyboard navigation, responsive axe scans and runtime/CSP errors. Its unique database, Redis queue, private objects and dedicated captured-mail container are cleaned. CI runs it alongside the existing full regression and dependency audit. Production JavaScript has a 200 KiB gzip entry/preload budget and 170 KiB per-chunk budget. Heavy charts, rich editor and PDF remain lazy. These are build regression budgets, not field performance results.

Affected files: API app/config/HTTP/proxy/server and compiled worker health; frontend HTML/theme bootstrap/app boundary; package runtime file lists; root scripts/CI/ignore rules; release Dockerfile/Compose/nginx/environment example; budget, production, HTTPS smoke and PDF-fixture scripts; HTTP/environment/recovery tests; README, architecture/API/testing/security/deployment/progress documentation. No business collection, schema migration or new product HTTP endpoint is introduced. Existing health endpoints remain the public probes; worker health is an operational command.

## Corrections found during verification

- The first cold container build (run 39139299994) failed because legacy offline deployment packaging requires registry metadata not populated by a frozen install. The final Dockerfile uses a separate filtered, offline, frozen production-install stage and preserves workspace links. Runtime checks verify native Argon2/contracts, non-root users, absent source/tests/development tooling and worker readiness. A warm local packaging probe alone was not accepted as cold-build proof.
- Run 39139727885 built the images but found a YAML flow-list comma splitting the tmpfs options into two mounts. Quoting the complete option fixes the actual daemon startup error.
- Run 39140227893 started healthy non-root API/web/worker containers and verified HTTPS headers/cookies/CSRF, then registration correctly returned 503 because production requires encrypted SMTP and the shared local mailbox was plaintext. The smoke fixture now uses a dedicated STARTTLS mailbox and explicitly trusts its generated public certificate. Production TLS verification was not disabled. Worker-profile cleanup was also made explicit. Superseded run 39140614068 was canceled and is not counted as passed.
- Run 39140912514 passed real HTTPS registration, captured STARTTLS email, onboarding, persistent work and the rich editor, then exposed nginx's missing `.mjs` MIME mapping in the actual PDF preview. An explicit JavaScript module mapping now covers PDF workers; WebAssembly retains its correct MIME type. The [upstream MIME table](https://raw.githubusercontent.com/nginx/nginx/release-1.30.6/conf/mime.types) lists JavaScript `.js` without `.mjs`. The revised smoke records bounded failure diagnostics. Static review also fixed its timing capture after context closure and made keyboard traversal account for the application's intentional main-content focus.
- Run 39141536756 passed the PDF worker preview/exact private download and saved-task charts, then scanned the marketing entry fade before its opacity reached one. The revised harness waits for the actual marketing opacity and finite appearance transitions before contrast scanning, matching the established foundation suite. This early failed scan is not counted as passed.
