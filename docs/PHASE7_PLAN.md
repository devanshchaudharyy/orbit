# Phase 7 — delivery planning

Implement milestones, sprint lifecycle/board, timeline/Gantt, finish-to-start dependencies, workload planning and delivery tracking. Stop after Phase 7. Reuse current project authorization, original versions, transactions, task statuses, design tokens and keyboard-accessible dialogs.

- Planning metadata is separate from task content: start date, entered estimate in hours, milestone, sprint and prerequisite task IDs. Scheduling changes the existing due date transactionally and preserves other task fields. Both task and planning versions protect edited snapshots. Dependencies stay within one project, reject self/duplicate/cyclic edges, and describe blockers and scheduling conflicts without silently moving dates or blocking task completion.
- Managers/project owners manage milestones, sprints and capacity. Current non-guest project collaborators plan tasks. Guests read authorized planning only. Archives block writes. Deletion/revocation immediately denies access.
- Milestones have a target date and explicit open/delivered status alongside actual linked-task progress. Sprint states are planned/active/completed, with one active sprint per project. Start records commitment; completion freezes actual delivery and explicitly carries unfinished tasks to backlog or a planned sprint. Completed sprint history is immutable; planned sprint deletion returns tasks to backlog.
- Timeline/Gantt shares server filters and paginated task records, with labeled dependency relationships and actual dates. Sprint board reuses transactional task-status moves; equivalent dialogs support keyboard/touch. Workload uses entered estimates split across assignees and calendar days, with business-day capacity from explicitly entered weekly hours. Unknown estimates, unscheduled work and unassigned work remain visible. No invented capacity, velocity, actual time or burndown.
- Responses paginate task rows at 100. Up to 50 milestones and 50 sprints per project; project planning snapshots are bounded at 5,000 active tasks and return an explicit limit error beyond that. Workload windows are at most 90 UTC days. Server summaries describe all authorized project work, not just loaded rows. Live snapshots are not immutable across concurrent edits.
- Use original HTML/CSS/SVG timeline presentation and existing drag-and-drop primitives; no new provider, chart/editor SDK or service. No Phase 8 realtime/comments/notifications.

Verify strict contracts and date/workload helpers; real database isolation, races, graph cycles, rollback, carryover, capacity, archive/revocation/deletion and persistence; browser flows, conflicts, failures, keyboard/focus, direct refresh, both themes at 375/768/1440 and axe. Update docs/screenshots and Compose CI, run regressions, then commit/push and observe the resulting workflow. Local Docker/WSL/restart acceptance stays deferred.
