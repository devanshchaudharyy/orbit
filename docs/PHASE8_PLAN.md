# Phase 8 — collaboration

Scope: real-time project/task/planning updates, task comments, project discussions, explicit mentions, a private project notification inbox, live presence and the existing activity feed. Stop after Phase 8. Documents/files, analytics dashboards, AI, billing and global administration remain later phases.

Implementation bounds also include 20,000 messages per project, 200 sockets/process and eight sockets/user. Linked-message anchors verify current thread scope before reading from later pages. Client refreshes coalesce over 200ms, with a general IP budget of 600 requests/minute and unchanged stricter sign-in/mutation limits.

MongoDB persists plain-text messages, versions, soft-deletion tombstones and recipient notifications. Task comments notify current owners/assignees and explicitly selected eligible members; project discussions notify selected members. At most ten mentions, 4,000 characters and fifty rows per page. Notifications are in-app only. Archived projects are read-only; guests read discussions but cannot post, edit or mention. Authors edit their own messages; authors and project managers/owners may remove messages. Current parent/resource access is checked on every operation. Original versions prevent stale changes. Client UUIDs deduplicate retried creates; conflicting reuse fails. Message, recipient notifications and activity commit together under existing membership/project fences.

Socket.IO server/client 4.8.4 attach to the persistent API and same-origin Vite proxy. Cookie sessions, exact Origin, CSRF and verified onboarding guard handshake and subscriptions. Each socket has one server-authorized project room; room names cannot be supplied. Every outgoing refresh/presence delivery rechecks identity and project authority. Read-only session checks do not renew idle expiry. Session/resource changes and periodic checks remove revoked/expired subscriptions. No content is broadcast: committed MongoDB change streams send scoped invalidations; REST remains the source of truth. Reconnect/recovered streams resynchronize queries. Stream failures display degraded status. Presence is ephemeral, deduplicated by user and bounded; records remain durable independently of sockets. This phase supports one API process; Redis multi-node adapters and background workers are not introduced.

Add original responsive collaboration UI, task comment threads, explicit mention selection, draft-preserving errors/conflicts, versioned editing/removal, cursor pagination, read/unread inbox, connection feedback, retry and accessible keyboard/dialog behavior. Existing activity/history and task mutations refresh across sessions without replacing open edit snapshots.

Verify strict contracts, real MongoDB transactions, deduplication, rollback, parent substitution, guests, archive/revocation, deleted tasks/messages, private recipient feeds, stale versions, socket Origin/CSRF/session/subscription checks, two-session updates, reconnection and presence cleanup. Run existing regression, types/lint/build/tests, browser/theme/viewport/axe checks; retain screenshots and exact results. Commit/push to the existing private repository and observe CI. Windows Docker/WSL/restart acceptance stays deferred; remote Compose and the owned local replica-set fixture are recorded separately.
