# Phase 9 — documents and files

Implement only the original roadmap's documents, rich-text content, attachments, file management and document history. Existing project membership is the permission boundary; guests and archived projects are read-only. No analytics, AI, billing, cloud provisioning or deployment. Commit/push the verified phase to the existing private repository and observe CI.

Project documents use a pinned Tiptap editor with a server-validated JSON subset: paragraphs, headings, lists, quotes, code, rules, inline emphasis and safe links. No raw HTML, embedded scripts or remote images. Document saves and immutable revisions commit with activity under existing authority/project fences. Original versions reject stale writes; historical restore creates a new revision. Team members with task-write permission edit documents; authors and managers remove them. Bound projects to 200 active documents, 500 revisions per document, 50-row pages, 50,000 text characters and 56KiB JSON. Live updates preserve unsaved drafts and require explicit conflict reload.

Files can belong to the project, a current task/subtask or a current document. Support PNG/JPEG/WebP images, PDF, UTF-8 plain text, Markdown and CSV, up to 8MiB. Check signatures, extension/MIME agreement, text validity and filenames server-side. Generated object keys are private; user filenames never become paths. Every list, preview and download verifies current parents/resource access. Images, bounded text and PDF pages have real previews; downloads use safe disposition/no-store headers. PDFs render as canvas pages with self-hosted PDF.js, XFA disabled and no annotation scripting/viewer integration. No public storage URL or frontend storage credential.

Separate MongoDB metadata, repository/service/controller and storage adapters. Development/test can use a private disk adapter under ignored local storage; production requires S3. CI uses the existing private Garage bucket. Upload UUIDs plus content fingerprints deduplicate retries. Durable pending intents prevent unconfirmed objects from being served; finalize under a fresh authority transaction only after bytes persist. Removed metadata immediately hides objects even if physical deletion needs retry. A bounded reconciliation CLI cleans expired pending intents/deleted objects without introducing a worker. Document/task deletion hides retained attachments. Preserve durable revisions and handle unavailable stores explicitly.

Add Documents & files navigation, document collection/detail/editor/history/restore, scoped attachment controls, validated uploads, file search/type filters, rename/removal, previews/downloads, loading/empty/error and archived/read-only states. Preserve canonical direct routes and allowlisted section/document links through sign-in. Reuse semantic themes, Radix focus behavior and reduced motion.

Dependencies: Tiptap core/pm/react/starter-kit 3.32.0 (React19-compatible), PDF.js 6.4.299 (Node24-compatible), existing AWS SDK. Affected packages: contracts, API documents/storage/config/auth binary handler/realtime, web editor/document/file views, scripts/fixture/Compose verification, tests and phase documentation.

Verify contracts and malicious content; real MongoDB revisions/rollback/retries/grants; actual disk bytes and private S3/Garage operations; delete/reconciliation failures; browser-to-API document/file flows, original-version conflicts, live draft preservation, direct refresh, keyboard overlays, both themes at 375/768/1440px, axe and earlier regression. Record exact executed results and screenshots. Windows Docker/WSL/restart acceptance remains deferred; local disk verification and remote Garage CI are distinct evidence.
